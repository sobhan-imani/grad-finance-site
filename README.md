# دخل و خرج جشن فارغ‌التحصیلی — راه‌اندازی رایگان (با ورود تلگرام و نقش‌ها)

```
index.html                                  صفحه‌ی اصلی سایت
config.js                                   آدرس Supabase، کلید anon و نام ربات تلگرام
vendor/ , fonts/                            کتابخانه‌ها و فونت‌ها (سایت به CDN وابسته نیست)
schema.sql                                  ساختار دیتابیس، نقش‌ها، تاریخچه و فضای فاکتورها
supabase/functions/telegram-auth/index.ts   تابع ورود با تلگرام (Edge Function)
```

## نقش‌ها

| نقش | دیدن و خروجی اکسل | اضافه و ویرایش | حذف | مدیریت اعضا |
|---|:-:|:-:|:-:|:-:|
| مدیر (خودت) | ✓ | ✓ | ✓ | ✓ |
| ویرایشگر | ✓ | ✓ | ✗ | ✗ |
| بیننده | ✓ | ✗ | ✗ | ✗ |
| شرکت‌کننده | فقط صفحه‌ی «پرداخت من» | فقط فرستادن فیش خودش | ✗ | ✗ |
| در انتظار | ✗ | ✗ | ✗ | ✗ |

هر کس با تلگرام وارد بشه، اول «در انتظار» است و در تب **اعضا** برای تو ظاهر می‌شه تا نقشش رو تعیین کنی. اگه شماره‌ی تلگرامش توی لیست شرکت‌کننده‌ها باشه، با یک دکمه (داخل تلگرام) شماره‌ش تأیید می‌شه و خودش به صفحه‌ی پرداخت می‌ره؛ لازم نیست تو کاری بکنی. این محدودیت‌ها داخل خود دیتابیس اعمال می‌شن، نه فقط در ظاهر سایت. هر تغییری هم با اسم انجام‌دهنده در تب **تاریخچه** ثبت می‌شه، پس اگه ویرایشگری عددی رو عوض کنه، مقدار قبلی معلومه.

## ۱) دیتابیس Supabase

1. در supabase.com پروژه‌ی جدید بساز (منطقه مثلاً Frankfurt).
2. در `schema.sql` بخش ۱، `me@example.com` رو با **ایمیل خودت** عوض کن. فقط همین یک جا لازمه.
3. **SQL Editor** → کل فایل رو بچسبون → **Run**.

## ۲) حساب مدیر (خودت)

1. **Authentication → Users → Add user → Create new user**: همون ایمیل + یک رمز، و **Auto Confirm User** روشن. چون ایمیلش با بخش ۱ یکیه، خودکار مدیر می‌شی (ترتیب این مرحله و مرحله‌ی قبل مهم نیست).
2. **Authentication → Sign In / Providers**: گزینه‌ی **Allow new users to sign up** رو خاموش کن. ورود تلگرامی همچنان کار می‌کنه، چون کاربرهای تلگرام رو تابع ورود می‌سازه. خود ورود با ایمیل روی سایت پنهانه؛ برای ورود با ایمیلِ مدیر، آدرس سایت رو با `?email` آخرش باز کن (مثلاً `https://username.github.io/party-finance/?email`).

## ۳) ربات تلگرام

در تلگرام به **@BotFather** پیام بده:

1. `/newbot` → یک اسم و یک نام کاربری (مثلاً `PartyFinanceBot`). **توکن** رو که می‌ده نگه دار و به کسی نده.
2. `/setdomain` → ربات رو انتخاب کن → فقط دامنه‌ی سایت رو بفرست، بدون `https://` و بدون مسیر؛ مثلاً `username.github.io`. بدون این مرحله دکمه‌ی ورود روی سایت کار نمی‌کنه.
3. (مهم) بعد از اینکه سایت بالا اومد (بخش ۶) و با حساب مدیر وارد شدی، در تب **تنظیمات** دکمه‌ی «**راه‌اندازی دکمه‌ی ربات**» رو بزن. از اون به بعد هر کس ربات رو Start کنه، پیام خوش‌آمد با دکمه‌ی «ورود به سایت» می‌گیره، و دکمه‌ی منوی ربات هم سایت رو داخل خود تلگرام باز می‌کنه و **بدون هیچ کلیکی وارد می‌شه**. شماره‌ی شرکت‌کننده‌ها هم فقط وقتی سایت از داخل تلگرام باز بشه خودکار چک می‌شه، پس به دوستات بگو سایت رو از ربات باز کنن. (برای این کار پیام‌های ربات به تابع `telegram-auth` فرستاده می‌شن؛ چیزی در BotFather لازم نیست.)

## ۴) تابع ورود تلگرام (Edge Function)

**از داشبورد (بدون نصب چیزی):**
1. **Edge Functions → Deploy a new function → Via Editor**. اسمش رو دقیقاً `telegram-auth` بذار، محتوای `supabase/functions/telegram-auth/index.ts` رو جای کد پیش‌فرض بچسبون و **Deploy** کن.
2. در تنظیمات همین تابع، **Enforce JWT verification** (یا Verify JWT) رو **خاموش** کن. کاربر موقع ورود هنوز نشستی نداره؛ امنیت ورود با بررسی امضای تلگرام داخل تابع تأمین می‌شه.
3. **Edge Functions → Secrets** → یک secret به اسم `TELEGRAM_BOT_TOKEN` با مقدار توکن ربات اضافه کن.

هر وقت فایل تابع در این مخزن تغییر کرد، همین کار رو تکرار کن (کد جدید رو بچسبون و دوباره **Deploy** کن) تا نسخه‌ی روی Supabase هم به‌روز بشه.

**یا با Supabase CLI:**
```bash
supabase functions deploy telegram-auth --no-verify-jwt
supabase secrets set TELEGRAM_BOT_TOKEN=123456:ABC...
```

## ۵) پر کردن `config.js`

از **Project Settings → API**:
- `supabaseUrl`: آدرس پروژه، مثل `https://abcd1234.supabase.co`
- `supabaseAnonKey`: کلید **anon** یا **publishable** (عمومیه و امنه؛ **هیچ‌وقت** `service_role` یا `secret` رو اینجا نذار)
- `telegramBot`: نام کاربری ربات بدون `@`
- `supportIds` (اختیاری): آیدی تلگرام مسئول‌های مالی بدون `@`، مثلاً `['ali_finance', 'sara_fin']`. وقتی شماره‌ی کسی توی لیست نباشه، این آیدی‌ها به‌صورت لینک بهش نشون داده می‌شن؛ اگه خالی بمونه، فقط بهش گفته می‌شه به آیدی‌هایی که توی گروه اعلام شده پیام بده.

## ۶) گذاشتن روی GitHub Pages

مخزن **Public** بساز و فقط این‌ها رو آپلود کن: `index.html`، `config.js`، پوشه‌ی `vendor` و پوشه‌ی `fonts`. (`schema.sql` ایمیلت رو داره و `supabase/` هم لازم نیست؛ آپلودشون نکن.) بعد **Settings → Pages → Deploy from a branch → main / root**.

## ۷) دعوت دوستان

1. لینک ربات (یا سایت) رو براشون بفرست. با تلگرام وارد می‌شن و پیام «درخواست دسترسی‌ت ثبت شد» رو می‌بینن.
2. تو در تب **اعضا** با یک کلیک تأییدشون کن: «بیننده» یا «ویرایشگر». همون لحظه صفحه‌ی خودشون باز می‌شه.
3. اسم نمایشی هر نفر رو هم همون‌جا می‌تونی عوض کنی؛ همین اسم در تاریخچه و ستون‌های «ثبت‌کننده» می‌آد.
4. «برداشتن دسترسی» عضو رو از لیست حذف می‌کنه؛ اگه دوباره وارد بشه، به‌عنوان درخواست جدید ظاهر می‌شه.

**شرکت‌کننده‌ها (پرداخت سهم):**
1. در تب **شرکت‌کننده‌ها** با «ورود از شیت» فایل ثبت‌نام (Excel یا CSV) رو وارد کن. ستون «شماره تماس» لازمه و هر نفر بعداً با همون وارد می‌شه؛ «نام»، «گرایش» و «تعداد مهمان» هم خونده می‌شن. عنوان ستون‌ها لازم نیست دقیق باشه (مثلاً «شماره تماس (ترجیحاً موبایل)» یا «تعداد مهمان‌ها» هم شناخته می‌شه). تعداد مهمان می‌تونه «۲»، «۲ نفر»، «دو نفر» یا «ندارم» باشه؛ هر چی رو که مطمئن نباشه، قبل از وارد کردن نشونت می‌ده تا چک کنی. اگه لیستت به‌جای شماره تماس، «شماره دانشجویی» داره، اون هم کار می‌کنه. اگه توی خونه‌ی شماره چیز دیگه‌ای هم نوشته شده (مثلاً آیدی تلگرام، یا دو شماره که کنار یکی «تلگرام» نوشته)، فقط شماره‌ی موبایل برداشته می‌شه (اونی که «تلگرام» کنارشه) و متن کامل توی یادداشت اون نفر می‌مونه. کسی که شماره‌ی درستی نداره هم با برچسب «بدون شماره» وارد می‌شه؛ تا شماره‌ش رو در پنجره‌ی خودش ننویسی خودش نمی‌تونه وارد سایت بشه، ولی پرداختش رو می‌تونی دستی ثبت کنی.
2. با «ویرایش اطلاعات پرداخت» شماره کارت، **مبلغ پیش‌فرض سهم** (برای خود هر نفر) و **مبلغ هر مهمان** رو بنویس. مبلغ هر نفر خودکار می‌شه «سهم خودش + تعداد مهمان × مبلغ هر مهمان». برای کسی که مبلغ دیگه‌ای داره، در پنجره‌ی همون نفر «مبلغ کل» رو دستی بنویس.
3. هر نفر سایت رو از داخل ربات باز می‌کنه و «📱 تأیید شماره با تلگرام» رو می‌زنه؛ شماره‌ش از خود تلگرام گرفته و با لیست چک می‌شه (تایپ کردن لازم نیست). اگه شماره‌ش توی لیست نباشه، بهش گفته می‌شه به آیدی‌هایی که توی گروه اعلام شده پیام بده؛ تو شماره‌ی اون نفر رو در پنجره‌ی خودش به شماره‌ی تلگرامش عوض کن (یا اضافه‌ش کن) و بگو دوباره دکمه رو بزنه. کسی که سایت رو توی مرورگر باز کنه، فقط دکمه‌ی «باز کردن ربات در تلگرام» رو می‌بینه؛ شماره رو هیچ‌جا نمی‌شه تایپ کرد. بعد از وصل شدن، مبلغ (با جزئیات مهمان‌ها) و شماره کارت رو می‌بینه و عکس فیش رو می‌فرسته (عکس روی گوشی خودش فشرده می‌شه).
4. فیش‌ها در همون تب زیر «فیش‌های در انتظار بررسی» میان؛ با «تأیید» مبلغ به سهم نفرات در بودجه اضافه می‌شه، با «رد» دلیلش به خود شخص نشون داده می‌شه.
5. اگه کسی نقدی داد یا فیش رو مستقیم برای خودت فرستاد: روی اسمش در تب **شرکت‌کننده‌ها** بزن → «+ ثبت پرداخت این نفر» → مبلغ (خودکار مبلغ باقی‌مونده‌ش پر می‌شه)، و اگه داری عکس فیش → «ثبت و تأیید پرداخت». پرداخت همون لحظه تأیید و به سهم نفرات اضافه می‌شه و وضعیت اون نفر هم درست می‌شه. برای این کار از «+ سهم» در تب بودجه استفاده نکن؛ اون فقط بودجه رو زیاد می‌کنه و اون نفر «پرداخت نکرده» می‌مونه.
6. **چند نفر با یک شماره:** اگه دو نفر با یک شماره ثبت‌نام کرده باشن (مثلاً یکی دوستش رو هم ثبت‌نام کرده)، موقع ورود از شیت هر کدوم جدا ثبت می‌شه و کنار اسمشون «شماره‌ی مشترک» می‌آد؛ همون اسم دو بار با یک شماره هم یک نفر حساب می‌شه. صاحب شماره بعد از ورود، بالای صفحه‌ی پرداخت بین اون‌ها جابه‌جا می‌شه و برای هر کدوم جدا فیش می‌فرسته. در پنجره‌ی هر نفر هم می‌تونی دستی شماره‌ی کسی رو که قبلاً ثبت شده بدی؛ سایت می‌پرسه و هر دو رو نگه می‌داره.

## نکته‌ها

- دکمه‌ی ورود تلگرام فقط روی دامنه‌ای کار می‌کنه که با `/setdomain` ثبت کردی (روی `localhost` یا باز کردن مستقیم فایل کار نمی‌کنه). ورود با ایمیل فقط با `?email` آخر آدرس سایت نشون داده می‌شه.
- کاربرهای تلگرامی در Supabase با یک ایمیل ساختگی مثل `tg123456@telegram.local` ذخیره می‌شن؛ این ایمیل واقعی نیست و چیزی بهش ارسال نمی‌شه.
- داخل تلگرام بعضی نسخه‌ها دانلود فایل رو پشتیبانی نمی‌کنن؛ برای خروجی اکسل سایت رو در مرورگر باز کن.
- پروژه‌ی رایگان Supabase بعد از حدود یک هفته بی‌استفاده بودن متوقف می‌شه؛ داده‌ها می‌مونن و با **Restore** برمی‌گرده.
- شماره‌ای که داخل تلگرام با دکمه فرستاده می‌شه رو تلگرام امضا می‌کنه و فقط شماره‌ی خودِ همون حساب قبول می‌شه؛ تایپ کردن شماره هم در سایت نیست. برای اینکه این قانون داخل خود دیتابیس هم اعمال بشه (نه فقط در ظاهر سایت)، دستور SQL «ورود فقط با تلگرام و شماره‌ی مشترک» رو یک بار در SQL Editor اجرا کن؛ همون دستور به صاحب یک شماره‌ی مشترک اجازه می‌ده بقیه‌ی هم‌شماره‌ها رو ببینه و براشون فیش بفرسته.
- دکمه‌ی ورود از telegram.org بارگذاری می‌شه؛ اگه روی شبکه‌ای telegram.org یا Supabase باز نشد، مشکل از دسترسی شبکه است.
